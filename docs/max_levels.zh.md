# MAX_LEVELS 安全值参考

`PT_MAX_LEVEL`、`LC_MAX_LEVEL`、`SP_MAX_LEVEL` 控制游标路径数组
`paths[]` 与暂存节点数组 `rt[]` 的大小。它们是编译期配置宏；应在包含实现
头文件之前定义。

如果 `MAX_LEVELS` 太小，树过深时会在根分裂或新建节点链时越界写穿
`paths[]`。下表给出在 `size_t` 可表示的最大数量（`SIZE_MAX`）下，按最坏
情况（每个节点都处于最小占用 `FANOUT/2`）计算出的、保证不可能溢出的最小
`MAX_LEVELS`。

## 公式

piecetab 与 spantree 的叶节点和内节点使用相同 fanout：

```
MAX_LEVELS = ceil(log_b(SIZE_MAX))
b          = FANOUT / 2   （整数向下取整）
```

linecache 的叶 fanout 独立：

```
MAX_LEVELS = ceil(log_b(SIZE_MAX / lf)) + 1
b           = LC_FANOUT / 2         （整数向下取整）
lf          = LC_LEAF_FANOUT / 2    （整数向下取整）
```

当 `LC_LEAF_FANOUT == LC_FANOUT` 时，linecache 的值与下表 piecetab /
spantree 的值一致。

## 安全默认值

当前库默认值：

- `PT_FANOUT = 31` → `PT_MAX_LEVEL = 17`（64 位）/ `9`（32 位）
- `LC_FANOUT = LC_LEAF_FANOUT = 62` → `LC_MAX_LEVEL = 13`
- `SP_FANOUT = 62` → `SP_MAX_LEVEL = 13`

64 位的 `PT_MAX_LEVEL = 17` 在 32 位与 64 位构建上都安全

快速规则：

- 64 位 `size_t`：piecetab 默认 `PT_FANOUT = 31` 需要
  `PT_MAX_LEVEL = 17`；linecache/spantree 默认 `FANOUT = 62` 需要
  `MAX_LEVELS = 13`。
- 32 位 `size_t`：默认值也安全（`PT_FANOUT = 31` 需要 9，
  `FANOUT = 62` 需要 7）；覆盖为更小 fanout 时请查表。

## 使用方法

- 如果保持库默认值，无需定义 `MAX_LEVELS`；内置默认值安全。
- 如果覆盖 `PT_FANOUT`、`LC_FANOUT`、`LC_LEAF_FANOUT` 或 `SP_FANOUT`
  为更小的值，请将对应的 `MAX_LEVELS` 至少设为表中对应 `size_t` 位宽的值。
- 示例：64 位构建使用 `PT_FANOUT = 4` 时必须传 `-DPT_MAX_LEVEL=64`。

树代码在每次增加层级的操作之后都加入了
`assert(levels < MAX_LEVELS)`，因此 debug 构建会在路径数组被破坏前发现
`MAX_LEVELS` 过小的问题。
