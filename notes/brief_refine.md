# 代码精炼要诀

本文件记录 piecetab / termfeed 代码精炼（refine）实验中的核心经验。

（注意：核心格式铁律在 AGENTS.md，如果你没读过，请先读 AGENTS.md 确保不违反铁律。当前文件所有精炼都要在**不违反铁律**的前提下进行）

## 核心信条

**精炼不是为了减行数，而是为了减杂质。** 25 行限制是工具，不是目标。为了凑行数引入 flag、拆分函数、或制造短路逻辑，都属于庸工。改完若不如改前清晰，就是倒退。

**精髓一句话：计算自然的值，让值引导决策。不要预设答案（flag），然后去核对。**

四种浪费（自查信号）：

| 浪费 | 典型表现 |
|---|---|
| 预制 flag | 先设 flag，后面再检查 |
| 特例分支 | `if (levels == 0)` 单独提前 return |
| 多余变量 | 声明了函数后半节不出现 |
| 大块分支 | `if { r=...; if (r != OK) return r; }` 可收成单行 |

## 条款详解

### 一 数据导向：让数据自己说话

**[1] 先计算，后判断**——把复杂条件中的公共子表达式提到前面，让判断变简短：

```c
// 繁
if (!ptM_ishole(p, cc-1) && !ptM_ishole(rt, 0) && ...)
// 简
hL = ptM_ishole(p, cc-1), hR = ptM_ishole(rt, 0);
if (!hL && !hR && ...)
```

**[2] 自然数据流代替人工 flag**——计算一个值，让数据本身告诉你答案，而非先设标记后核对。例（`ptD_mergeleaf`）：坏 = 先预制 `merged` 再核对"空间够不够"；好 = `d = pt_min(右大小, 左剩余空间)` 的值自然区分部分/完全合并。

注意：`merged` 仍然必要——它记录"是否合并了整片右叶"，这是数据流无法直接回答的布尔问题。关键区别：`merged` 是**计算的结论**，不是**预设的标记**。flag 只带 1 bit 信息，同类判断各自提前 return（每个终止条件直接 return，不预置 term 标记）。

**[3] 统一 > 特例**——不要为边界情况写单独分支，融进主循环。例（`ptC_freeze` 的 `levels==0`）：坏 = 单独 `if (levels == 0) return;`；好 = 主循环天然处理（`for (l = tree->levels; l > 0;) { --l; if (l >= tree->levels) break; ... }`）。同类：不可达的 switch `default:` 消除，越界兜底改主路径后单行 if（§34）。

**[4] 重复分支问"同一数据的不同来源？"**——三个函数共享同一解码逻辑 → 抽参数化 helper，入口各剩 2-4 行。问过才合并：语义有微妙差异的判定等价但保守不合并（合并的收益要大于等价论证的成本）。

### 二 视觉简洁：简练是减杂质，不是减行

**[5] 用宏，不用 cast**——`(const char *)p->data` → `ptN_lit(p, cc-1)`。宏不仅短，而且语义自明。

**[6] 逗号表达式**——同一逻辑单元（同类字段、同一 category）的赋值连成一句：`key->type = TF_TYPE_UNICODE, key->event = TF_EVENT_PRESS;`。多行赋值暗示"独立步骤"，逗号表达"一起发生"（原子修改的语义指引），且省行数。散开写仅当赋值之间夹着计算/判断。纯赋值的单行 `if` 块用 `,` 取代 `{ }`：`if (del > 0 && (r = pt_remove(C, del)) != PT_OK) return r;`。

**[7] 提交语义：`return expr, 状态;`**——"提交"（状态复位、计数更新）缩到 return 后：`if (b == 0x07 || b == 0x9c) return tfD_cskey(S, key), TF_OK;`。动机不是缩行而是视觉语义：一眼看到 return 的意图。块状裸 return（`if (x) { stmt; ...; return; }`）同样收编为单语句或 if/else 链。单语句 `if (x) return;` 不算裸 return——递归基例、OOM 尽力而为、API 校验等天然形态可保留。**但单 return 优先**：能调整逻辑使函数只有一个 return（值最后统一返回），比提交语义更强——提交语义仍是多出口，多出口必要才用。

**[8] 变量少即是多**——删掉只出现一次的栈变量（直接调函数或声明在 for 里）。但**不要重复计算有副作用的表达式**：无副作用且编译器能优化时，重复调用比引入临时变量更清晰。声明尽量内联进表达式（`lua_setfield(L, -2, yyjson_get_str(key))`），只留必须的（循环游标/输出参数）。

**[9] 单行形态**——`if (cond) stmt;` 不加 `{}`（两行块 → 一行），else 同理，仅多语句才保留。`case X: { ... }` 是杂质——声明全提函数头（C89 本来如此），case 体无声明即无需大括号。

**[10] 单行函数与 off 保护**——clang-format 只拆不合，手写单行函数必须 clang-format off 保护。仅用于真正简单（~90 字符内）的函数；长函数硬压单行伤可读性。**off 只允许保护单行函数本体，禁止为覆盖率保护单行 if/表达式**；off 注释带附加文字会被 clang-format 静默忽略，指令必须纯 `/* clang-format off */`。两行式（签名 + `{ 实现 }` 各一行）用于实现单行但签名超宽时。

**[11] 混合初始化声明：非初始化变量在前**——读者必须先扫过非初始化变量（需要留意），初始化变量自解释可略过；初始化打头，后面的裸变量容易被漏看。`int len, cp = -1, mods = 0;` 正，~~`int i = 0, cp, r;`~~ 错。

**[12] 写字符串用带截断 helper**——同函数族的 `writes(buf, len, s)` 与 `snprintf("%s")` 完全等价（拷贝+截断+NUL+返回字节数），且免 size_t cast。

### 三 循环与迭代：形态即语义

**[13] 循环递增一律 ++i**——前缀递增是全库铁律。后置 `i++` 仅当递增表达式的值被使用；`out[j++] = c` 这类"写入并前进"的复合操作可保留后置——它是复合语义，不是纯递增。

**[14] 循环形态判定**——
- 有 init/cond/inc 完整三要素 → for
- 纯"跳过到某条件" → while 或 for+continue
- 终止条件单一且可前置 → `while (cond)` 而非 `for(;;)`——条件在头部是信息密度；`for(;;)` 只留给多体内退出点的循环
- `for(;;) { if (X) break; ... }` 中 X 明显可前置 → 必须写 while：break 式骨架的退出条件藏在体内中部，多退出点不构成豁免理由（体内另有 return 不影响主退出条件前置）
- `while (cond) { ...; update; }` 尾有循环变量更新 → 写 `for (; cond; update)`：update 进 for 头与 cond 相邻，循环控制集中一处，体只剩业务逻辑。**例外**：update 非纯循环推进（夹业务副作用）或体与 update 长依赖时保持 while
- 空 for 体用 `continue` 不用 `;`——clang-format 对空 for 体振荡

**[15] 查表循环避免运行时 strlen**——`strlen(tbl[i].name)` 的指针来自运行时索引，编译器无法静态折叠。表字段存 `len`，初始化用 `sizeof(name) - 1`（编译期常量），宏包一层免重复写名字：`#define TFK_MOD(name, mod) {(name), (int)(sizeof(name) - 1), (mod)}`。

**[16] 顺序字节读取用单一 Cursor 推进**——读多字节序列（utf8 回扫/步进）必须一次定位 + Cursor 顺序推进（每次推进更新状态、跨 piece 安全、支持负 delta），禁止每字节 seek/locate 重建 Cursor——每次 seek 丢弃连续状态（AGENTS.md 铁律：Cursor helper 严禁 locate）且重做定位。utf8 后退：一次定位后回扫 ≤4 字节窗口（负回退 + 顺序读 + 尾部找 lead），窗口 4 字节必含 lead。

### 四 性能与正确性：先于简练

**[17] API 形态杜绝 O(n²)**——简练清晰是为了更好理解最优化实现，不能本末倒置。"看着顺眼"的接口可能是性能陷阱：按索引从 buf 头重扫的参数访问 API，调用方写成 `arg(S,1) + arg(S,2) + ...` 即 O(n²)，且该 API 形态**诱导**调用方写出 O(n²) 代码。判定标准：每次调用是否"从头重扫"？同一数据是否被重复定位？是 → 改成单次扫描/迭代器。

**[18] 迭代器形态三坑**——① 返回字段头指针导致 in/out 参数方向混杂，签名撒谎：用 `int` + `const char **pf` 两 in/out 对称。② 耗尽后置空指针会**重启**（空指针兼首调/耗尽双重语义）→ 耗尽置尾哨兵，幂等返回 0。③ 界面臃肿（数组+struct+dflt 契约）是抽象错误的信号——首版全包而复杂，切回迭代器后整体消失，净减 ~130 行。

**[19] 数据入口归库自身**——接收调用方 malloc 的指针数组、内部排序后直接存指针 = 指针生命周期依赖调用方（如 `lua_tostring` 指针随 GC 失效，接口层无保证）。改单字段接口，库内部自行构建/持有内存，绑定层循环逐项喂入。判断标准：**被存储的数据必须由库复制进自己的内存，接口只接受值/单指针，不接受指针数组**。

**[20] 迭代算法设计期做均摊分析**——"每个叶容器从 root 重新下降找 hole"实现简单但 O(H·L)，review 被打回返工。**凡是"循环里重复定位"的设计，写设计文档时就要给均摊论证**；给不出的，改为"从当前位置继续"的迭代器。

**[21] bug 教训**——
- **减法要数清缓冲边界**：当前字节从未进缓冲时，只应 `len -= 1`，原 `-= 2` 多减 1 字节，且测试注释固化了错误期望——review 时要追问"为什么少一个字节"，别接受测试注释当真相
- **贪婪解析要留退出路径**：允许"到达终止符也算匹配成功"时，终止符会被吃成内容，键名空 → 解析失败。匹配只在分隔符前成立，键名优先

### 五 命名与分类：名字里藏领域

**[22] 命名里藏领域**——`ptK_cowedit → ptD_cowpaths`：它是删除流程中的 COW 路径分裂，不是通用工具。函数名反映分类（D=删除, K=光标）而非机制（cow）。`de → d`：简称够用时就不需要全称。

**[23] 工具宏命名与位置**——命名：全大写、不带名字空间字母（`TF_NAMEBUF_SZ` 而非 `tfK_NAMESZ`）。位置：全项目通用的函数式宏集中放 implementation 前部（include 后、NS_BEGIN 前）；数据表宏与常量宏留在绑定位——**只有全项目通用的才挪前部**。表元素计数宏一处定义全库复用，让 `for` 条件保持单行（免 ntbl 变量）。

**[24] 绑定层内部函数不带分类码**——分类码（`xxX_name`）只属**库头文件**；绑定层（lua/*.c）内部工具函数一律 `xx_` 前缀（lpt_charstep 非 lptM_charstep）。绑定层无多模块混用，分类码纯噪声。

### 六 与 clang-format 相处

**[25] 对抗三招**（长条件/嵌套三元被拆坏时）——
- 取反 if 条件，让单行短分支在 if 侧而非 else
- 嵌套三元被拆成错位缩进 → "逐步覆盖"：先赋默认值，再按优先级从低到高覆盖
- 多条件 if 超 80 列被拆 → 预计算标志变量，if 恢复单行（C89 允许块内连续声明）

**[26] 悬挂续行 = 代码坏味，改代码消除**——逗号表达式 return / 多操作数续行被拆成远列悬空对齐 = 悬挂写法，接受即放弃可读性，也是列宽微调就崩的脆弱形态。修法：**改代码而非调格式**——提行为条件赋值 + 单行 return，或重组表达式让续行自然落在语句内部。禁 clang-format off 保单行（§10）。

### 七 注释与重构纪律

**[27] 函数头注释全删**——**函数头不写注释**。删前先问"为什么写"，按序处置：① 代码晦涩 → 改实现（首要手段！注释是晦涩实现的下策）；② 输入契约（调用方必须满足）→ `assert`；③ 输出契约（调用方依赖的返回/副作用语义）→ 函数体内注释（return 附近）；④ "做什么" → 写进 design 文档；⑤ 代码自明 → 直接删。体内零散多行注释同款处置：压成单行只留必要内容；长篇论证（顺序理由、预算推导、不变量）在 design 文档强调，代码只留一行索引式短注。多行注释的存在本身是信号——先问"这信息值几行"。**注释最容易与实现不同步**——改代码后必须同步 design 与精炼文档（有过 bug 记录在文档、文档却未同步长达一年的教训）。

**[28] 重构前列隐性行为清单**——重构前从被删代码/注释提炼行为清单（缺字段默认值、空字段、截断、吞末字段、前导跳过、判定规则），每项映射到既有测试（无测试的补新断言）。隐性契约的保障三级：① **消除**（最优先）——重构使约束成为自然数据流或结构保证；② **使用处/实现处注释**——约束绑定生效位置，改代码必然看到；③ **测试兜底**——只负责验证，不该是唯一保障。区分"可达分支"与"结构保证分支"：结构不变量可直接去掉检查，不必补测试。流程：先跑基线 → 重构 → 全量测试 + 覆盖率对比（行 100%、分支 ≥90% 不倒退）。

**[29] 行数预算按伪代码 ×2 估**——设计文档预算"净增 24 行"，实际 ~50 行——伪代码不含 C89 声明块、错误传播、assert、断行。**预算失真一倍是常态**：按伪代码 ×2 报，或设计文档直接写 C 骨架。

**[30] 上升+下降合并为单 iter 函数**——树上"找下一个 X"应写成**一个** `pt_next` 式函数（ascend 找可行层 → descend 落点），而非 find/next/descend 三个小函数分散逻辑。首次调用用哨兵初始化统一（如 `paths[0] = root.children` 后"从头找"即首调），消灭 findfirst/findnext 两套入口。

**[31] 意外修改先评估来源**——diff 与预期不符时：可能是用户改的，也可能是 formatter 或其他进程改的。先正确评估——语义等价性、风格倾向、可能来源——拿不准就停下来询问，**绝不允许对未知修改自作主张保留或回滚**（教训：回滚了一处用户为 clang-analyzer 改的前置 void 写法，白回滚一场）。

### 八 测试与覆盖率

**[32] 测试期望会固化行为**——测试注释断言"内容应为 X"时，先质疑 X 是否符合协议语义，再信实现。多轮 review + 100% 覆盖率不保证语义正确——只保证行为稳定。

**[33] 覆盖率缺口先问"能消除吗"，再问"能覆盖吗"**——绝大多数缺口是**可以改写掉的逻辑**，不是不可达代码，豁免清单是最后手段。手段按序：
1. **行覆盖转分支覆盖**——单行 `if (cond) return ...;` 条件求值即该行已执行，拆成两行则 return 行未执行 = 行缺口。错误推送抽 helper 且 **helper 由可测路径共用**（fopen 失败与 fwrite 失败共用同一 ioerr helper，fopen 可测即覆盖 helper 体）；"先计算再判断"（`int werr = fwrite(...) != len; if (werr) return ...;`——werr 是计算结论非 flag）。禁 clang-format off 保单行（§10）
2. **相信 API，删防御检查**——宿主语言/调用方保证的枚举、越界、非 NULL 契约检查删掉。删前确认契约在 API 文档（严格输入，放松输出）
3. **统一 > 特例**——条件分支幂等时无条件化（缓存刷新恒执行：同树幂等，异树修 stale）
4. **尾调用消除 else 块**——if/else if/else 改提前 return + 尾调用（error 函数不返回，编译器不报）
5. **死分支删除**——恒真条件（所有对象必有 metatable → 去 if）、不可达 default 消除（code 恒在枚举内 → 删 default，越界兜底放 switch 后单行 if——条件求值即覆盖，§34）
6. **三元替代 if/break**——循环内 `if (end) seg = end+1; else break;` → `seg = end ? end+1 : seg+seglen`（三元两路均可执行）
7. **测试盲区先查参数求值顺序**——`f(g(), h())` 里 h 先 error 时 g 根本没执行——先确认目标行真的可达，再补测试
8. **gcov 行号映射**——条件编译（`#if LUA_VERSION_NUM < 502`）分支、宏展开分支的未覆盖行可能是映射偏移（X macro 展开映射到调用行，执行调用即整行覆盖），先跑测试确认再决定豁免（§34）

豁免清单只留：结构保证、平台分支、依赖外部配置的分支。

**[34] X macro 集中错误码定义，且不损行覆盖**——`#define LX_ERRORS(X) X(1, name1) X(2, name2) ...` 一处维护 code+name，switch 内 `#define LX_ERROR_CASE(code, name) case code: pushliteral(#name)` 展开。**宏展开代码的 gcov 行号映射到宏调用行——执行 switch 即整行覆盖，各 case 无需逐个触发**。配套：不可达 `default:` 消除，越界兜底改为 switch 后单行 if（条件求值即覆盖）。

### 九 Lua 绑定特例

**[35] 跨运行时 API 先实测语义差异**——LuaJIT 的 `lua_tointegerx(3.5)` 返回 3 且 isint=true（不检查小数），5.5 语义正确——跨运行时行为不一致。绑定内自实现统一版，不依赖平台 API 语义。**凡是跨 5.1/5.5/LuaJIT 的 API，先实测语义差异再直接用**。

**[36] lua_next 循环：pop 后栈索引语义变化**——`while (lua_next(L, idx))` 循环内栈为 `[table, key, value]`——**pop value 后 key 到栈顶（-1）**，`-2` 变成外层数据。重构把检查内联进条件时**误把检查挪到 pop 之后** → 检查的是 value/外层数据。规则：**栈索引敏感的取值/检查必须发生在 pop 之前**；重构后跑全量测试（§28 回归网价值）。

**[37] 错误返回用稳定字符串名**——解码失败返回 `nil, err_name, err_pos`（三值，不堆四值）——err 是**稳定字符串**（`"unexpected_end"` 等，非自由文本），`.d.lua` 用 `@alias err_code "..." | "..."` 限死全集——用户可字符串比较，LuaLS 校验拼写。不导出数字常量表（小 API 不配错误表）；错误码字符串用 `lua_pushliteral`（编译期 strlen）。

**[38] null 哨兵 = registry 固定表**——JSON null → **registry 里的固定空表**（luaopen 建一次，模块属性暴露），decode 推同表、encode 用 `lua_rawequal` 身份比较识别。对比 lightuserdata：表身份比较**两路都可测**（哨兵表 vs 普通表），无"宿主语言无法制造 lightuserdata"的结构分支。**表是宿主语言原生可造的唯一对象 → 哨兵优先选表**。

**[39] 同类赋值按类型分类抽 builder**——把零散的 `key->type = ...` 按类型分类，每个静态类型一个 builder：`tfK_unicode(key, cp)` / `tfK_keysym(key, sym)` / `tfK_function(key, n)`。**公共字段不入 builder**（来源多变，统一入参反而臃肿）——踩坑：builder 强制默认值会覆盖先行的合法赋值（测试当场抓住），正解是 builder 只设类型专属字段，公共字段在入口统一兜底。动态类型路径（表命中、特殊报告）不用 builder，保持原样。太通用的名字是坏味道：一行 helper 若名字比函数体还重，直接内联。
