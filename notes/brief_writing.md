# brief_writing.md — C 书写纪律

> 只管“怎么写”，不管“怎么设计 / 重构”（语义原则见 `notes/brief_refine.md`，测试见 `notes/brief_tests.md`）。
> 写 / 改 C 代码前逐条对照本文件；提交前按 §9 自查。
> 示例可用真实名字（如 `ptN_lit`）；但条款理解不得依赖库内背景——需要先懂某个领域概念才能看懂的例子不要写。

## 1. 签名与函数形态

- 函数签名必须单行，且不超过 80 列；超宽就缩短参数名或重构，不许折行。
- 函数体 25 行软限 / 30 行硬限；计划模式下规划的代码严禁超 30 行硬限，实不能则陈替代方案。
- 函数体禁止悬挂缩进、禁止远列逗号对齐。
- 严禁 label + goto。
- 不写函数头注释；函数说明写 `notes/design_*.md`，in/out 契约写函数体内；函数逻辑不自明就改名或改实现。
- 注释必须纯英文；注释详义归 README.md。
- Clean C：保持 C89 与 C++03 的交集，保证 C 与 C++ 编译器均可编译；所有变量声明在函数或块开头，不使用 C99/C11 扩展。
- 保留 C++ 编译所需的类型转换，去除其他不必要的类型转换。
- 标准规定的 signed/unsigned 混合运算（赋值、比较、实参传递）是良定义的模运算，**不要为 mix 写 cast**：`n += d;`、`off + d`、`f(C, d)` 直接写（结果须落在目标 `size_t` 范围内）。只有 MSVC `/W4` 可能警告的窄化（如 `int → char`、`size_t → unsigned`）才用 cast 让转换意图显式；不得为 `-Wsign-conversion` 这类非默认警告添加 cast 或分支。目标是 `-Wall` / MSVC `/W4` 无警告。

## 2. 大括号与块

- 禁止孤立大括号块（仅为包住声明 / 临时作用域）。
- 单行 `if (cond) stmt;` 不加 `{}`；else 同理。
- if/else 两侧一简单一复杂时，简单语句放 if 侧（单语句保持单行不加 `{}`），复杂侧按需保留 `{}`。
- 只有多语句才保留 `{}`；多语句块不写孤立 else。
- 允许 `if (cond) return;` / `continue;` / `break;`；纯块内裸 `return;`/`continue;`/`break;` 按优先级选形态：① 无 `else` 也无裸跳转；② 提交语义；③ 行数最少；④ 行数相同时裸 `return` 优于 `else`。
- 禁止“没有其他语句的嵌套 if”：外层仅作内层守卫时写 `if (a && b) ...`（内层是复合块也一样）；同一外层下若只有多个纯 `if`，逐个展开；合并后超宽先变通（如把可前置的赋值移出），确实无法才保留嵌套。
- 禁止“两个分支实质操作完全相同”的 if/else，包括只差正负号 / 方向的加减分支。反例：
  ```c
  if (d < 0)
      n -= (size_t)(-d);
  else
      n += (size_t)d;
  ```
  应写成 `n += d;`，前提是结果落在 `n` 的 `size_t` 范围内（`d < 0` 时 `|d| <= n`，`d > 0` 时不溢出）。`ptrdiff_t` → `size_t` 是良定义的模转换；反而 `-d` 在 `d == PTRDIFF_MIN` 时是 UB。
- 尽量不用 `else`：能用早退 / 提交语义写成无 `else` 时优先；无 `else` 会明显复杂 / 不美观 / 语义强依赖对比 / 两侧都多行时不强求。
- 注意“`else` 变体”：`if (err) { ...; return err; } return OK;` 实为错误分支早退、成功落到末尾；若成功路径只是末尾返回，可先返回成功再处理错误路径：
  ```c
  if ((r = ...) == OK) return OK;
  if (需要清理) ...;
  return r;
  ```

## 3. 单行 / 短函数

- 签名 + 实现整行 ≤80 列时，写成一行的短函数。
- 仅当“整行超 80，但签名单独、实现单独各 ≤80”时用两行式：
  ```c
  static int pt_empty(pt_Node *n)
  { return ...; }
  ```
- 连续的双行短函数聚类在一起，外面包一次 `/* clang-format off */` / `/* clang-format on */`；不要每函数单独包。
- `clang-format off` **只保护双行函数**；单行函数放保护区外由 clang-format 管理；多行函数一律不得放进 off 区。
- 无依赖的单行函数放在当前逻辑块的双行函数区下方、保护区外，与相邻短函数聚类，不散落在长函数之间。
- 长函数禁止硬压单行。
- 单行 struct/typedef 会被 clang-format 拆开时，同样用 off/on 保护，可与相邻单行声明聚类。

## 4. 命名

- 每个库使用唯一前缀（如 `pt` / `lc` / `at` / `sp` / `ut` / `cg` / `tf` / `tm` / `comp`）；具体见对应 `notes/brief_*.md` / `notes/design_*.md`。
- 公共 API `at_advance`；内部函数 `ptI_append`（`I` = 分类码）；函数宏同函数——所有函数名最多只能有一个下划线。
- 库内类型 `pt_Node`（typedef 写两遍）；数据宏 `PT_OK`（不带名字空间）；分类码只属函数 / 宏，不进类型名。
- 绑定层内部函数不带分类码——统一 `lpt_` / `ltf_` 前缀；Lua 绑定导出函数以 `L` 开头且不带分类码。
- 内部函数必须符合 `ptX_name`：前缀 + 分类码 + 小写名，全名只能有一个下划线；带尾下划线的内部函数允许调用其他带尾下划线的内部函数。
- 局部变量和参数禁止下划线；struct field 可以有下划线。
- 例外：参数名镜像同名 struct field 并用于直接赋值时，允许保留该下划线（如 `ptA_alloc(..., size_t obj_size)` 形态）。
- 内部类型名尽量不带大写分类码 / 命名空间；只有参考对象本身也带时才跟随参考对象。
- 公共 API 名称不参与这条改名约束。

### 4.1 分类码与函数名分工

命名先看逻辑块的分类码代表什么：

- **名词块**：分类码已表示主要对象。主入口若写成 `xxNoun_verbnoun`，去掉重复名词，写成 `xxNoun_verb`。名词块内并列多个 `verb1noun` / `verb2noun` 时统一去掉名词。
- **动词块**：分类码已表示主要动作。主入口允许 `xxVerb_verb`，例如 `lcD_remove`、`spD_remove`。动词块内并列多个 `verbnoun1` / `verbnoun2` 时统一去掉动词，例如 `xxD_rmrange` / `xxD_rmleaf` -> `xxD_range` / `xxD_leaf`、`spF_filterrange` / `spF_filterleaf` -> `spF_range` / `spF_leaf`。
- **同一对象、不同动词并列时，动词是区分信息，保留**。例如 `rt` 对象组保持 `fillrt` / `insertrt` / `flushrt`，`spF_fillrt` / `spF_appendrt` / `spF_flushrt` 也保持各自动词。
- 只有整组都能转成有意义、不撞名、不造假同族的名字时才统一改名；否则整组保留。`appendrt` / `appendspan` / `append` 不能因为共享 `append` 就统一处理：`appendrt` 属于 `rt` 对象组，`appendspan` 属于 append 子流程。
- 改名必须匹配库里既有的动词语义：`insert` = 插入后光标不动，`append` = 插入并让光标追尾到内容之后。名字与实际光标契约不符时必须改名，例如 piecetab 的插入主入口按实际语义叫 `ptI_append`，而不是 `ptI_insert`。

- 正例：`ptI_append`、`ptI_insertrt`、`ptI_fillrt`、`ptD_balancenode`、`ptC_freeze`；反例：`ptI_split_ins`、`ptD_range_rt`。

## 5. struct field

- stb 单头文件内：函数声明前只保留 typedef 前向声明；公开 struct 的完整定义统一放在函数声明之后的独立 `/* structure */` 段。
- 不暴露的内部类型不要在公开 header 里 typedef；公开 struct field 需要引用时写 `struct pt_Node *`。
- 内部类型的完整定义（`typedef struct pt_Node { ... } pt_Node;`）放在 implementation 区。
- 很短的 struct（如只有两个 field）允许一行，用 clang-format off/on 保护；单行 struct 不需要 field 注释。
- 非单行 struct 每个 field 单独一行并带英文注释；位域、数组同样要注释；风格与参考实现对齐。

## 6. 声明与依赖

- 不做不必要的前向声明；能通过重排定义消除就重排。
- 不保留未使用的声明、未使用的参数；确需保留时用 `(void)` 表达。
- 内部函数不做防御性参数校验；参数合法性由公共入口统一拦截。依赖前置条件用 `assert` 表达，不返回错误码或默默兜底。
- 不写无谓 cast。
- 抽相同结构代码时优先用当前已有 helper，不要“先无脑抽新 helper，再考虑应用”。
- 抽出的 helper 若只剩对其它 helper 的调用，应把调用内联回各使用处，不保留“只转发调用”的高参数 helper。
- 抽出的 helper 参数过多 = 抽象失败：先内联回去再重新考虑抽象，不要直接回退成大段 `if/else for`。
- **内部 helper 不设计“返回多个值”的接口**：多输出参数是 smell；能拆函数就拆、能让调用方按需重算就重算、能用单返回值就用单返回值。只有公共 API 在 C 无法返回多值且语义必须成组时，才允许 out 参数。
- 简单字段映射（如 `is_end ? enext : snext`）可提供函数宏集中一次，避免多处重复；宏名按内部函数命名规则（如 `ptN_lit`，最多一个下划线）。复杂 / 带副作用的重用必须有明确语义，不为复用而复用。
- **禁止一次性变量**：变量只在紧邻的下一个表达式使用一次，且内联后不增加复杂度、不超宽时，必须内联。
- 只做相等 / 不等比较的代数计数器（如 epoch）允许回绕：不要为“避免回绕”无脑升宽到 `size_t`；设计时说明回绕后的行为与可接受风险。
- 局部变量声明尽量贴近使用位置：Clean C 允许在函数内层块开头声明；只在某块内使用的变量就声明在该块内。例外：块外也使用；或移入内层块不能减少行数（如外层已按类型集中声明）。
- 同一个派生值在提前 return 的分支和后续都要用时，可直接在声明处初始化（提前分支会 return，声明处的值可安全用于后续）。若分支不 return 且修改了派生值的来源，分支内要同步更新本地变量。
- 同一行同时设置索引与父指针时，把 parent 赋值内联进 index 计算：`i = ptK_idx(C, p = ptK_parent(C, l), l), cc = ptN_cc(p);`，不写成先 `p = ...` 再 `i = ...`。
- 多个循环游标声明按参考实现的写法排列。
- 同类型变量尽量合并到同一行声明，未初始化变量在前、带初始化变量在后；不同类型声明行除数组 / 连续性 / 逻辑依赖等特殊情况外，按“从长到短”排列。
- 函数内出现多种数值类型时检查是否真的必要；只接收某函数返回值并传给同族 API 的变量，用该函数返回 / 参数的自然类型；除非类型差异自然（API 返回类型、参数、同类比较），尽量合并类型，避免为类型而 cast。

## 7. 表达式与提交语义

- 简单赋值后紧跟 `return OK;` 时优先写成提交语义：`return (*out = e), PT_OK;`。
- 任何“无条件单步 / 同逻辑清理后紧跟 `return OK;`”且整行 ≤80 时，都应写成提交语义（如 `return ptD_stitch(...), PT_OK;`）。
- 多个同逻辑 void / 赋值操作后紧跟返回，合并不超宽可全部收入：`assert(...), n->bytes[i] -= rem;` / `return ptD_makechain(...), ptD_stitch(...), PT_OK;`。
- 提交语义不切分自然逻辑中的连贯操作：`return` 前有两个平行 / 对称操作时，要么全部收进同一个 `return ..., PT_OK;`，要么全部留在 `return` 前，禁止只合并其中一个。
- **C89 中 void 函数不允许 `return void_expr;`**；需要“调用 void helper 后按整数结果返回”时，可让 helper 返回 `int`（0/1 仅作提交语义），调用方写 `return helper(...), 0;`。判断能否删除该 `int` 的唯一前提是内部是否还需要这个 0/1 提交语义。
- 尽量避免块状裸 return；纯块内裸 `return;` 与 `else` 的取舍按 §2 优先级。
- `r = expr; if (r != status) ...` 这类“赋值后立即按状态判断”尽量内联为 `if ((r = ptD_range(...)) != PT_OK) return r;`；NULL 查找同理 `if ((a = lookup(...)) == NULL) return err;`。
- 指针特殊规则：`if ((v = expr) == NULL)` 因 `== NULL` 超 80，但 `if (!(v = expr))` 能放进 80 时允许 `!` 形式；其余情况优先显式 `== NULL` / `!= NULL`。
- 相同逻辑组合的代码，合并后整行 ≤80 时允许用逗号表达式合并（可先在不改变逻辑的前提下重排让相近代码相邻）；不同步骤（先取指针、再用指针算位置）不硬并。
- 同一逻辑的赋值 + `assert` + `(void)` 可按逗号表达式合并（如 `r = ptD_range(...), assert(r == PT_OK), (void)r;`）；合并后若 `if` 块只剩这一条语句，去掉大括号。
- `assert` 为保证后续使用不越界时尽量贴近使用处，优先级：① 使用处本就在逗号链中 → 插到紧邻该表达式之前；② 唯一更贴近的方式要额外加括号（如包进函数参数）→ 按可读性取舍；③ 使用点是 `[]` 下标，不能把逗号表达式放进下标 → 写在外面：`assert(i < cc), child = (pt_Node *)n->children[i];`
- 循环内 `if (cond) break;` / `if (cond) continue;` 允许；能前置 / 重构时优先前置；禁止裸 `break;`/`continue;`。
- 优先 `for` 样式：`init; while (cond) body, incr;` 应写成 `for (init; cond; incr) body;`。
- `for (;;)` / `while (1)` 不是严禁：默认改写为条件在头部的写法；确认它最优（多退出点 / 状态机且主条件无法前置）时允许，但必须在交付 / 注释中说明理由。

## 8. 与参考实现同步

- 同族实现（B+ 树 / 单头库的移植、参考关系）优先同构：相同概念用相同命名、相同功能尽量相同实现、功能块与块内函数顺序保持一致；不要自行发明写法。
- 只有领域模型迫使差异时才允许特殊实现，并把差异收在最小边界内。
- 参考实现同一函数已改成 early-return / no-`else` 形态时，同族对应函数必须同步形态；领域差异只允许改变分支内容，不允许无理由保留旧级联 `else`、`for (;;)`、裸 `continue` 等写法。

## 9. 必查清单

提交 / 交付前检查（细则见各节）：

- [ ] 函数签名单行 ≤80 列；函数体 ≤30 行（软限 25）；计划模式未超硬限；无 label + goto
- [ ] 无函数头注释；注释纯英文；无悬挂缩进、无孤立大括号、无“没有其他语句的嵌套 if”
- [ ] 无多余前向声明；无未使用声明 / 参数；无无谓 cast；无一次性变量
- [ ] 局部变量声明贴近使用 / 同类型已合并 / 未初始化在前 / 声明行从长到短 / 数值类型自然
- [ ] 相似结构已复用 helper；无“只转发调用”的 helper；无多输出参数 helper
- [ ] 内部函数名最多一个下划线；分类码只属函数 / 宏；绑定层前缀无分类码（`lpt_` / `ltf_`）
- [ ] 公开 struct 完整定义在 `/* structure */` 段；内部类型不在公开 header typedef；非单行 struct 每 field 一注释
- [ ] 短函数已聚类并正确使用 clang-format off/on（单行函数在保护区外）
- [ ] if/else 符合单行短分支规则；无“两个分支实质相同”；能无 `else` 的已去掉
- [ ] signed/unsigned 混合运算直接写，无 mix cast；无为 `-Wsign-conversion` 等非默认警告写的 cast / 分支
- [ ] 提交语义已使用且未切分连贯操作；赋值后立即查错 / 查空已合并（≤80 时）
- [ ] 同逻辑逗号表达式已合并（含赋值 + assert + (void)）；assert 已贴近使用处
- [ ] 内部函数无防御性参数校验，前置条件用 `assert`；入口统一校验
- [ ] 无裸 `return;`/`continue;`/`break;`；默认无 `for (;;)`，保留时有说明
- [ ] 与参考实现同构，无自行发明写法
- [ ] 已跑 clang-format（必过）
- [ ] 新增行数若逾改量之半，已在交付中详述其理
