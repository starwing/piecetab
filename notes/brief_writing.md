# brief_writing.md — C 书写纪律

> 本文件只管“怎么写”，不管“怎么设计/重构”。语义原则见 `notes/brief_refine.md`。
> 写/改 C 代码前必须逐条对照本文件；提交前必须按本文件自查。

## 1. 签名与函数形态

- 函数签名必须单行，且不超过 80 列；超宽就缩短参数名或重构，不许折行。
- 函数体禁止悬挂缩进、禁止远列逗号对齐。
- 不写函数头注释；函数逻辑不自明就改名或改实现。
- Clean C：保持 C89 与 C++03 的交集，保证 C 与 C++ 编译器均可编译；所有变量声明在函数或块开头，不使用 C99/C11 扩展。
- 保留 C++ 编译所需的类型转换，去除其他不必要的类型转换。
- 有符号 → 无符号的算术转换是良定义的模运算；无符号 → 有符号的越界转换才是实现定义。需要模算术时直接写 `p->n += d;`（前提是结果落在 `p->n` 的 `size_t` 范围内），不得为 `-Wsign-conversion` 这类非默认警告添加 cast 或分支；目标是 `-Wall` / MSVC `/W4` 下无警告。
- 禁止“两个分支实质操作完全相同”的写法，包括只差正负号/方向的加减分支；应合并为一条无符号模算术语句（如 `p->n += d;`），或用 `size_t` + 方向参数的单一 helper 表达方向。

## 2. 大括号与块

- 禁止孤立大括号块，例如 `{ ... }` 仅为了包住声明/临时作用域。
- 单行 `if (cond) stmt;` 不加 `{}`；else 同理。
- if/else 两侧一个简单一个复杂时，把简单语句放 if 侧，复杂语句放 else 侧；简单侧只有一条语句时保持单行不加 `{}`，复杂侧按需保留 `{}`。
- 只有多语句才保留 `{}`；多语句块不写孤立 else。
- 禁止“没有其他语句的嵌套 if”：只要外层 `if` 体没有其他语句、仅作为内层 `if` 的守卫，即使内层体是复合块，也应写成 `if (a && b) ...`；同一外层下若只有多个纯 `if`，也逐个展开为 `if (a && ...)`。若合并后的 `if` 行超限，先尝试变通（例如把其中可前置的赋值移出 `if`），确实无法变通才保留嵌套。
- 禁止“两个分支实质操作完全相同”的 if/else，包括只差正负号/方向的加减分支。反例：
  ```c
  if (d < 0)
      p->n -= (size_t)(-d);
  else
      p->n += (size_t)d;
  ```
  应写成 `p->n += d;`，前提是结果落在 `p->n` 的 `size_t` 范围内（`d < 0` 时 `|d| <= p->n`，`d > 0` 时不溢出）。`ptrdiff_t` → `size_t` 是良定义的模转换；反而 `-d` 在 `d == PTRDIFF_MIN` 时是 UB。目标是 `-Wall` / MSVC `/W4` 无警告；`-Wsign-conversion` 不是默认警告，不得为了它写分支或 cast。
- 尽量不用 `else`：能用早退/提交语义写成无 `else` 时，优先写成无 `else`。例外：无 `else` 会变得复杂/不美观/语义强依赖对比/if 和 else 都是多行/会明显增加行数等，可保留 `else`。
- 注意“`else` 变体”：`if (err) { ...; return err; } return OK;` 实际上是错误分支早退、成功分支落到末尾 `return OK`。若成功路径只是末尾返回，可先返回成功，再处理错误路径，例如：
  ```c
  if ((r = ...) == OK) return OK;
  if (需要清理) ...;
  return r;
  ```

## 3. 单行/短函数

- 函数签名 + 实现整行不超过 80 列时，直接写成一行的短函数。
- 只有“签名 + 实现超过 80 列，但签名单独和实现行分别不超过 80 列”的函数，才用两行式：
  ```c
  static int xx_empty(xx_Edge *e)
  { return ...; }
  ```
- 连续出现的短函数尽量聚类在一起，外面只包一次 `/* clang-format off */` / `/* clang-format on */`，不要每个函数单独包。
- 长函数禁止硬压单行。
- 单行 struct/typedef 若会被 clang-format 拆开，同样用 off/on 保护，并可与相邻单行声明聚类。

## 4. 命名

- 内部函数必须符合 `xxX_name`：前缀 + 分类码 + 小写名，全名只能有一个下划线；带尾下划线的内部函数允许调用其他带尾下划线的内部函数。
- 反例：`atN_split_node`、`atO_side_count`、`atD_rmrange_rt`。
- 正例：`atN_splitnode`、`atO_sidecount`、`atD_rmrange`。
- 局部变量和参数禁止下划线；struct field 可以有下划线。
- 例外：参数名镜像同名 struct field 并用于直接赋值时，允许保留该下划线（参考库 `xxP_init(..., size_t obj_size)` 即此形态）。
- 内部类型名尽量不带大写分类码/命名空间；只有参考对象本身也带时才跟随参考对象。
- 公共 API 名称不参与这条改名约束。

## 5. struct field

- stb 单头文件内：函数声明前只保留 typedef 前向声明；公开 struct 的完整定义统一放在函数声明之后的独立 `/* structure */` 段。
- 不暴露的内部类型（如 `at_Node`）不要在公开 header 里 typedef；公开 struct field 需要引用时写 `struct at_Node *`。
- 内部类型的完整定义（`typedef struct at_Node { ... } at_Node;`）放在 implementation 区。
- 很短的 struct（例如只有两个 field）允许写成一行，并用 clang-format off/on 保护；这种单行 struct 不需要 field 注释。
- 没有写成单行的 struct，每个 field 必须单独一行并带英文注释，说明含义；注释风格与 spantree.h/piecetab.h/linecache.h 对齐。
- 位域、数组等同样要注释。

## 6. 声明与依赖

- 不做不必要的前向声明；能通过重排定义消除就重排。
- 不保留未使用的声明、未使用的参数；确需保留时用 `(void)` 表达。
- 不写无谓 cast。
- 抽相同结构代码时，优先使用当前已有的 helper，不要“先无脑抽新 helper，再考虑应用”。
- 如果抽出的 helper 内部只剩下对其他 helper 的调用（例如只有 `atN_copyraw(...); atN_fixlinks(...);`），则应把这些调用直接内联到各使用处，而不是保留一个“只转发调用”的高参数 helper。
- 如果抽出的 helper 参数过多，说明抽象失败：应先将抽出的代码内联回去，再重新考虑抽象；不要直接回退成大段 `if/else for` 结构。
- 局部变量声明尽量贴近使用位置：Clean C 允许在函数内层块开头声明，若变量只在某个块内使用，就声明在该块内，不做外层变量隐藏。
  - 例外：该变量在块外也使用，则不要放进内层块；
  - 例外：移入内层块不能减少行数时不做（例如外层已按类型集中声明）。
- 同一个派生值在“提前 return 的分支”和后续都要用时，可以直接在声明处初始化，例如 `int i, r, cc = atN_cc(n);`；因为提前分支会 return，声明处的值可安全用于后续。
- 如果分支不 return，并且分支内修改了派生值的来源（如 `atN_cc(n)` 的 `n` 被更新），则分支内应同步更新本地变量：`update(n), cc = atN_cc(n);`。
- 同一行同时设置 `i` 与 `p` 时，标准写法是把 parent 赋值内联进 index 计算：
  ```c
  i = xxK_idx(C, p = xxK_parent(C, l), l), cc = xxN_cc(p);
  ```
  不写成先 `p = xxK_parent(...), i = xxK_idx(..., p, ...)`。
- 这类多个循环游标声明时，按 linecache.h 的写法排列，例如 cutrange 中为 `int i, k, kl, cc, l = ...;`。
- 同类型变量尽量合并到同一行声明，且未初始化变量放在前面，带初始化变量放在后面。
- 多条不同类型声明行之间，除非有数组、数组连续性、逻辑依赖等特殊情况，按“从长到短”排列声明行。
- 函数内出现多种数值类型时，检查是否真的必要；变量若只是接收某函数返回值并传给同族 API，应使用该函数返回/参数的自然类型。除非类型差异是自然的（如 API 返回类型、函数参数、与同类型值比较），否则尽量合并类型，避免为了类型而 cast。

## 7. 表达式与提交语义

- 简单赋值后紧跟 `return OK;` 时，优先写成提交语义：
  ```c
  return (*out = e), AT_OK;
  ```
- 不只赋值：任何“无条件单步/同逻辑清理后紧跟 `return OK;`”且 `return ..., AT_OK;` 整行 ≤80 时，都应写成提交语义，例如：
  ```c
  return atI_moverights(...), AT_OK;
  ```
- 多个同逻辑的 void/赋值操作后若紧跟返回，只要合并不超宽，可全部收入提交语义：
  ```c
  assert(...), n->bytes[i] -= rem;
  return atN_makespace(...), atN_setleaf(...), AT_OK;
  ```
- 尽量避免块状裸 return：
  ```c
  *out = e;
  return AT_OK;
  ```
- `r = expr; if (r != status) ...` 这类“赋值后立即按状态判断”，只要 if 只是判断刚赋的值，即使 if 体是复合块也尽量内联；合并后整行 ≤80 时写成：
  ```c
  if ((r = expr) != status) return r;
  ```
  NULL 查找同理：
  ```c
  if ((a = lookup(...)) == NULL) return err;
  ```
- 指针特殊规则：若 `if ((v = expr) == NULL) ...` 因 `== NULL` 超出 80 列，但 `if (!(v = expr)) ...` 能放进 80 列，允许用 `!` 形式。只要不是这种“必须靠 `!` 压列宽”的情况，仍优先写显式的 `== NULL` / `!= NULL`。
- 相同逻辑组合的代码，合并后整行 ≤80 时允许用逗号表达式合并；不要把不同步骤硬并成一行，例如“先取指针、再用指针算位置”应分成两步，而“算 start 和 end”可合并为 `start = ..., end = ...;`。
- 若几条更新形式更接近（如同一 `ins` 同时更新 leaf 和 tree 总量），在不改变逻辑的前提下可先重排让相近代码相邻，再用逗号合并；例如：
  ```c
  leaf->bytes[i] -= ins, T->bytes -= ins;
  atM_addpath(anc, idx, L, 0, -(ptrdiff_t)ins);
  ```
- 同一逻辑的赋值 + `assert` + `(void)` 也按逗号表达式合并，例如：
  ```c
  r = atD_deleteedge(...), assert(r == AT_OK), (void)r;
  ```
  若合并后所在 `if` 块只剩这一条语句，则去掉该 `if` 的大括号。
- `assert` 若是为保证某个值的后续使用不越界/不非法而存在，应尽量贴近使用处。贴近优先级：
  1. 如果该使用处本来就在一个逗号链中，把 `assert` 插到紧邻该使用表达式之前，不增加括号，最优先：
     ```c
     // 原来
     assert(i < cc);
     other, call(i), other;
     // 优先
     other, assert(i < cc), call(i), other;
     ```
  2. 如果唯一能更贴近的方式是要把它包进函数参数里（例如 `seek(C, (assert(obj), obj), xxx)`），会额外增加括号；此时可贴可不贴，按可读性取舍。
  3. 如果使用点是 `[]` 下标运算符，不能把逗号表达式放进下标内（部分编译器不友好），此时把逗号表达式写在外面：
     ```c
     assert(i < cc), child = (at_Node *)n->children[i];
     ```
- 循环内 `if (...) { ...; break; }` 能前置/重构时，不许写孤立 break。
- 优先使用 `for` 样式：`init; while (cond) body, incr;` 应写成 `for (init; cond; incr) body;`；只有 `while` 才能自然表达时才用 `while`。

## 8. 与参考库同步

- B+ 树/单头库优先与 spantree.h、piecetab.h、linecache.h 同构：
  - 相同概念使用相同命名；
  - 相同功能尽量使用相同实现；
  - 功能块顺序和块内函数顺序保持一致；
  - 不要自行发明写法。
- 只有领域模型迫使差异时，才允许特殊实现，并把差异收在最小边界内。

## 9. 必查清单

提交/交付前检查：

- [ ] 所有函数签名单行且 ≤80 列
- [ ] 无悬挂缩进、无孤立大括号
- [ ] 无多余前向声明
- [ ] 局部变量声明已贴近使用/同类型已合并/未初始化在前/不同类型声明行从长到短/数值类型自然且无多余 cast
- [ ] 相似目的代码已检查并复用 helper，无重复结构代码
- [ ] 内部函数名最多只有一个下划线（带尾下划线的宏族 helper 可调用同类 helper）
- [ ] 公开 struct 完整定义在函数声明后的 `/* structure */` 段；函数声明前只有 typedef
- [ ] 不暴露的内部类型不在公开 header typedef；完整定义在 implementation 区
- [ ] 非单行 struct 的 field 每行一个且带英文注释；单行短 struct 有 clang-format off/on 保护
- [ ] 短函数已聚类，并用 clang-format off/on 保护
- [ ] if/else 符合单行短分支规则
- [ ] 无“两个分支实质相同”的 if/else（含仅正负号/方向不同的加减分支）
- [ ] 有符号增量直接写 `p->n += d;`（结果须在 `size_t` 范围内），无为了 `-Wsign-conversion` 等非默认警告而写的 cast 或等价分支
- [ ] 无“没有其他语句的嵌套 if”（已展开为 `a && b`）
- [ ] 能无 `else` 的简单分支已去掉 `else`
- [ ] 提交语义已使用，无块状裸 return
- [ ] 赋值后立即查错/查空已按条件内赋值合并（≤80 时）
- [ ] 同逻辑可合并的逗号表达式已合并（含赋值 + assert + (void)），不同步骤未硬并
- [ ] 与参考库同构，无自行发明写法
- [ ] 已跑 clang-format
